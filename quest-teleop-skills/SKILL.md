# 概要

Meta Quest 3 のコントローラ6DoFポーズで、ロボットアームSO-101(フォロワー)を操作する
LeRobotサードパーティプラグインを生成し、動作確認まで実施する。
本スキルは Quest 3 + SO-101 + Jetson での実機構築(2026-07)で検証済み。

これまでのデバイス(ジョイスティック/MIDI/SpaceMouse)との違い:
1. **トランスポートがネットワーク**(WebXR/WSS) — デバイスドライバではなくWebページ
2. **絶対位置IK制御** — 手の変位がグリッパ(EE)位置を直接動かし、逆運動学で関節角を解く
3. **座標系の較正**(joint_offsets_deg)が必須

# 前提知識(コード生成前に必ず理解すること)

1. **トランスポートはWebXR一択が現実的**: ADB+APK方式(oculus_reader)はMeta開発者
   アカウント+サイドロードが必要。WebXRならQuest標準ブラウザでページを開くだけ。
   ただしWebXRは**セキュアコンテキスト必須** — 自己署名証明書のHTTPSサーバを
   プラグインに内蔵する(標準ライブラリのみで実装可能、reference.md §1)。
2. **制御はクラッチ式・絶対位置+IK**: グリップ握った瞬間の手の位置が原点、
   手の変位×スケールがEEターゲットを動かし、ダンプト最小二乗IK(URDF実寸チェーン、
   numpyのみ・placo不要)で腕3関節を解く。手首2関節は手の傾きに直結し、
   その分の位置ズレは腕が自動補償(EEにグリッパフレームを使う)。
3. **座標系の較正が必須**: IKは「関節角0°=URDFゼロ姿勢(キャリブレーション中央)」前提。
   実機の0°がズレていると(特にWRAPPEDキャリブレーションの関節)、動きが歪む・
   反転して感じる。`joint_offsets_deg` を実測して補正する(Step 5)。
   **オフセット誤りはIK残差では検出不能**(モデル内部は無矛盾)— 人間の目視が唯一の検出器。
4. **安全設計**: IK残差ゲート(到達不能フレームは腕も手首も動かさず一括棄却)、
   関節レート制限、ストリーム停滞タイムアウト、起動時実姿勢同期+ホーミング。

# ワークフロー

## Step 1: ネットワーク疎通確認

- QuestとJetsonを**同じWiFi(同一SSID)**に接続。
- 切り分けの階段(reference.md §2): SSID一致 → QuestのIPへ `ping` →
  ページ取得カウンタ → WebSocket接続 → ストリーム受信。どの段で止まったかで原因が絞れる。
- QuestはMACランダム化のためARPでの特定は「ローカル管理ビット付きMAC」が手がかり。

## Step 2: サーバ・ページ疎通確認

- プラグイン内蔵サーバを起動し、Questブラウザで `https://<jetson>:8443/<token>/` を開く。
  **URLのVRキーボード入力は失敗しやすい** — 平文ヘルパ(`<ip>:8080` → 302転送)と
  「/」エントリ転送(履歴URL救済)を必ず用意する。
- 証明書警告は「詳細設定」→「アクセスする」(初回のみ)。
- **[Enter VR]で真っ暗になったら描画の問題**(ポーズ送信は動いている)。
  `immersive-ar`(パススルー)でセッションを取り、毎フレーム透明クリアする —
  現実のロボットを見ながら操作できるようになり、テレオペに最適。

## Step 3: ロボットアーム確認

- joystick-teleop-skills の Step 2〜3 と同一(ポート特定、シリアル排他、キャリブレーション)。
- **サーボバスの物理層に注意**: アームを手で動かす作業が多いため、ケーブル緩みによる
  「ID消失」「パケット破損」「全モーター無応答」が起きやすい。測定スクリプトは
  再接続リトライ必須(reference.md §6)。

## Step 4: コード生成

実証済みの操作系(右コントローラ):

| 操作 | 割当 |
|---|---|
| グリップ(中指) | クラッチ — 握った位置が手の原点、握っている間だけ追従 |
| 手の変位(クラッチ中) | グリッパ(EE)位置 ×motion_scale |
| 手首の傾き/ロール(クラッチ中) | wrist_flex / wrist_roll(1:1、腕が位置補償) |
| トリガ(人差し指) | グリッパ閉じ量(絶対+ソフトテイクオーバー、クラッチ独立) |
| A / B / スティック押込 | エピソード成功 / 失敗 / 再記録 |
| 反対の手のグリップ長押し | 人間介入フラグ |

### 実装上の制約(実機で踏んだもの。必ず守ること)

- **WebXR座標→ロボット座標**: WebXRは x=右, y=上, z=後ろ。ロボット(x=前, y=左, z=上)へは
  `[-dz, -dx, +dy]`。
- **手首ピッチの符号**: WebXRは「手を下に倒す」が**負**、URDF `+wrist_flex` は「先端下」。
  **符号反転(-1)が既定で必要**(設定で反転可能にしておく)。
- **IKのリミットは solver 内部で適用**: 解いた後にクランプすると残差ゲートをすり抜けて
  「静かに数cmズレた指令」になる。ユーザーリミット∩URDFリミットをIK反復内で適用し、
  クランプの影響を残差に正直に反映させる。
- **フレーム一括コミット**: IK棄却時は手首も動かさない(手首だけ動くとEEが手から離れて暴走)。
- **関節レート制限**: DLSの分岐飛びは1フレーム26°級のジャンプを起こす。IK出力に
  deg/s上限をかける。
- **グリッパはソフトテイクオーバー付き絶対マッピング**: 「係合時基準+トリガ増分」方式は
  トリガ0始まりだと**開く方向に動けなくなる**(実際に踏んだ)。トリガ位置=閉じ量、
  初回は現在値を拾うまで無効、が正解。
- **起動時は実姿勢同期→ホーミング**: configure()フックでロボットインスタンスを捕捉し
  (robot_gainsと同じ機構)、初回制御サイクルで実測姿勢をターゲットに。測定姿勢が
  リミット外ならクランプせずリミットを広げる(クランプすると起動ジャンプ)。
  その後 `home_position` へレート制限付きランプ — 「手はボタンを押した位置、
  アームはホーム姿勢」という認識しやすい原点対応になる。
- セキュリティ: アクセストークンでページ/WSをゲート(ただし利便のための転送ヘルパは
  トークンをLANに露出する — トレードオフを文書化し、無効化手段を設ける)。
  TLSハンドシェイクは**ハンドラスレッドに遅延**(accept ループで行うと沈黙TCP1本で
  サーバ全体が凍る)。

## Step 5: joint_offsets_deg の較正(このデバイス固有の必須手順)

1. テレオペ停止(ポート解放)を確認し、トルクを切る。
2. アームを**キャリブレーション中央姿勢**(上腕垂直・肘90°・前腕水平=URDFゼロ)に手で保持。
3. 全関節の度数を読み取り(**自動検出方式を推奨**: 動き出し→4秒静止を検知して記録。
   カウントダウン方式は非同期のやり取りでは窓を外しやすい)。
4. `joint_offsets_deg = -読み値`。正しく中央姿勢でキャリブレーションされた関節は≈0、
   WRAPPED関節は大きな値になる(例: 実測でelbow +86.9°)。
5. シミュレーションで検証: オフセット適用後の中央姿勢がURDF 0/EE≈[0.39, 0, 0.23]になること、
   手の前後上下左右の変位がEEの正しい軸に写ること。

## Step 6: 動作確認

- 段階順: ①ドライラン(ロボット未接続)でクラッチ/追従/リリース保持/ボタン
  ② `motion_scale=0.5〜0.7` で実機 ③ 感触調整。
- 確認観点: 起動時に動かないこと(実姿勢同期)→ ホーミング → グリップ握って
  手の各方向とグリッパの追従一致 / 手首の傾き方向 / トリガの拾い→開閉 /
  離した瞬間の停止 / ワークスペース境界でIK棄却により止まること。
- 方向が違うときの切り分け: 並進の歪み=オフセット較正、手首の反転=符号設定。
