# 対応VRヘッドセット デバイス別リファレンス

## Meta Quest 3(WebXR)【実機検証済み 2026-07-31】

| 項目 | 値 |
|---|---|
| 接続方式 | WebXR(標準ブラウザ、インストール不要)。同一WiFi必須 |
| ネットワーク | MACランダム化あり(ARPにはローカル管理ビット付きMACで現れる) |
| XRセッション | `immersive-ar`(パススルー)対応 — テレオペはこれ一択。`immersive-vr` はフォールバック(描画しないと真っ暗) |
| リファレンス空間 | `local-floor`(不可なら `local`)。座標: x=右, y=上, z=後ろ |
| ポーズ | `gripSpace` の position/orientation、表示レート≈72Hzで取得可能 |
| コントローラボタン | xr-standard mapping: buttons[0]=トリガ(アナログ) [1]=グリップ(アナログ) [3]=スティック押込 [4]=A/X [5]=B/Y、axes[2,3]=スティック |
| グリップ座標の癖 | 「手を下に倒す」=ローカルx軸の**負**回転(URDF +wrist_flex=先端下とは逆 → 符号反転が必要) |
| URL入力 | VRキーボードは打ち間違い多発。Questブラウザは非URL入力を**Web検索**にする。平文転送ヘルパ(`ip:8080`)+履歴URL救済の「/」転送を用意する |
| 証明書 | 自己署名は初回に「詳細設定→アクセスする」が必要。受け入れ前のTLS試行がサーバ側に `CERTIFICATE_UNKNOWN` を量産(ログ抑制推奨) |

プラグインでの割当: グリップ=クラッチ(位置制御)、トリガ=グリッパ閉じ量(絶対+テイクオーバー)、
A/B/スティック押込=成功/失敗/再記録、反対の手のグリップ長押し=介入。

未対応(将来拡張): ハンドトラッキング(WebXR `hand-tracking` feature — コントローラなしの
ピンチ操作)、Quest 2/Pro(同じWebXR APIなので profile 追加程度で動く見込み)。

## 新しいヘッドセット/入力方式を対応させる手順

1. ブラウザのWebXR対応を確認(`navigator.xr.isSessionSupported('immersive-ar')`)。
2. ページ側で `inputSources` のプロファイル文字列・gamepad mapping を実測ダンプし、
   ボタン配置を確定(Questのxr-standard前提が崩れる機種があり得る)。
3. グリップ座標系の軸方向(特にピッチ符号)を、クラッチ+傾け操作のキャプチャで実測。
4. パススルーの可否でセッションモードのフォールバック順を決める。
5. 実測結果を本ファイルに追記する。
