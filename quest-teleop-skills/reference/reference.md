# LeRobot 0.6.0 Quest(WebXR)テレオペレータープラグイン実装知見

Quest 3 + SO-101 フォロワー + Jetson での実機構築(2026-07-31)で得た知見。
実装の実例: `lerobot_teleoperator_quest`(WebXR + 絶対位置IK、pytest 42件、実機検証済み)。
プラグイン規約・座標系・キャリブレーション等の共通知見は
`../../joystick-teleop-skills/reference/reference.md` を参照。

---

## 1. WebXRトランスポート(内蔵HTTPS/WSSサーバ)

- **WebXRはセキュアコンテキスト必須** → 自己署名証明書のHTTPSをプラグインに内蔵
  (openssl CLIで初回生成)。WebSocket(RFC6455)受信も標準ライブラリで自前実装可能
  (マスク付きテキストフレーム+ping/pong+closeで十分。フラグメントは棄却で安全側)。
- ポーズは約72Hz(表示レート)でJSONテキストフレーム。`XRFrame.getPose(gripSpace, refSpace)`
  の position/orientation + gamepad(xr-standard: 0=トリガ 1=グリップ 3=スティック押込
  4=A/X 5=B/Y)。
- **TLSハンドシェイクはハンドラスレッドへ遅延**(`do_handshake_on_connect=False` +
  accept後にソケットtimeout設定)。acceptループ内でハンドシェイクすると、無言のTCP接続
  1本でサーバ全体が凍り、stop()もブロックする(実証済み)。
- 証明書受け入れ前のブラウザのTLS試行は `SSLV3_ALERT_CERTIFICATE_UNKNOWN` を量産する —
  `handle_error` をオーバーライドしてdebugログに抑制。
- **セキュリティ**: 無認証だとLAN上の誰でも偽ポーズを流してアームを動かせる。
  起動毎ランダムトークンでページ(`/<token>/`)とWS(`/<token>/ws`)をゲート。
  ページJSは `location.pathname` からwsパスを導出(トークンが自然に引き継がれる)。
  ただし利便のための平文転送ヘルパ(`:8080`→302)と「/」エントリ転送は**トークンを
  LANに露出**する — 利便/安全のトレードオフとして文書化し、`redirect_port=null` で
  厳格化できるようにする。

## 2. 接続の切り分け階段(実際に全部踏んだ)

1. **同一SSID**か(Jetson側: `iwgetid`)。
2. **ping疎通**(QuestはMACランダム化 — ローカル管理ビット付きMACがARPに出る)。
3. **ページ取得**: page_hitsカウンタ+接続元IPログを仕込む。0なら**URL入力の問題** —
   VRキーボードでの `https://ip:port` 入力は失敗しやすく、Questブラウザは
   URLと認識できない入力を**Web検索**にかける。対策: 平文ヘルパ(`ip:8080` だけ入力
   →302転送)と、履歴のURLを救う「/」エントリ転送。
4. **証明書警告**: 「詳細設定」→「アクセスする」。警告画面で止まるとTLSは成立するが
   ページ取得は発生しない。
5. **[Enter VR]で真っ暗**: 描画していないだけでポーズ送信は動いている(1639パケット
   受信しながら画面は黒、が実測)。`immersive-ar`(パススルー)+毎フレーム透明クリアで
   解決 — 現実のロボットを見ながらの操作になり、むしろ理想形。

## 3. 制御設計(クラッチ式・絶対位置+EE-IK)

- **クラッチ**: グリップ握下で手の現在位置をアンカー化。変位×`motion_scale` が
  EEターゲットを動かす。離すと保持、握り直すと新アンカー(ジャンプなし)。
- **IK**: URDF(`so101_new_calib.urdf`)の実寸チェーンをハードコードし、
  ダンプト最小二乗+数値ヤコビアン+ウォームスタート。3関節×位置3成分の正方系。
  numpyのみ(placo不要)。追従条件で残差0.1mm・約1ms/解(Jetson Orin実測)。
  rpy行列は `Rz@Ry@Rx`(URDF固定軸convention)— 間違えると最大43cmズレる。
- **EEターゲットはグリッパフレーム**(手首中心ではなく): 手首を傾けても腕が補償して
  グリッパが手に貼り付く。ただし手首だけで大きな腕動作を誘発する(60°チルトで肘64°)
  ことは操作者に伝える。
- **安全ゲート(すべて実機/レビューで実証した欠陥への対策)**:
  - 残差 > `ik_tolerance`(4mm)のフレームは**腕も手首も動かさず一括棄却**
    (手首だけ動かすとEEが手から離れて暴走する)。
  - ユーザーリミットは**IK反復の内側で適用**(外側クランプは残差ゲートをすり抜けて
    静かに69mmズレる)。
  - IK出力に**関節レート制限**(deg/s)— DLSの分岐飛びは1フレーム26°級のジャンプを生む。
  - オフセット誤りはIK残差では**検出不能**(モデル内部は無矛盾)。初回実機は低
    `motion_scale` + `--robot.max_relative_target` 必須。
- **手首ピッチの符号**: WebXRグリップ座標で「手を下に倒す」=負の回転、
  URDF `+wrist_flex`=先端下 → **-1の符号反転が既定で必要**。ロールも設定で反転可能に。
- **グリッパ**: トリガ位置=閉じ量の絶対マッピング+ソフトテイクオーバー(MIDIフェーダーと
  同じ方式)。クラッチから独立。**「係合時基準+増分」方式はトリガ0始まりで開けなくなる**
  設計欠陥(実際に踏んだ)。

## 4. 座標系較正(joint_offsets_deg)と初期位置

- IKの前提: lerobot度数 0°=URDFゼロ姿勢。WRAPPEDキャリブレーションの関節は0°=ホーミング
  時の姿勢になっており大きくズレる(実測: elbow +86.9°)。**ズレたまま動かすと
  「上下が反転している」ように感じる**(モデルと実機の幾何が乖離するため)。
- 較正手順: 中央姿勢(上腕垂直・肘90°・前腕水平)で全関節を読み、符号反転値をオフセットに。
  読み取りは**自動検出方式**(動き出し→静止4秒で記録)が確実 — カウントダウン同期は
  非同期チャットでは窓を外す(3回失敗した)。
- **起動時実姿勢同期**: configure()フックでフォロワーのインスタンスを弱参照で捕捉
  (robot_gainsフックと同居)し、初回制御サイクルで `bus.sync_read` した実姿勢を
  ターゲットに。同一制御スレッドなのでポート競合なし。実姿勢がリミット外なら
  **クランプせずリミットを広げる**(クランプすると起動ジャンプ指令になる)。
- **home_position**: 同期後にホーム姿勢(例: 折りたたみ)へレート制限付きランプ。
  「手はボタンを押した位置、アームはホーム」という人間が認識しやすい原点対応を作る。

## 5. 実機検証の記録(2026-07-31)

- ドライラン: 3001パケット(72Hz)、クラッチ7回、EEアンカー移動、リリースドリフト0.0°。
- IK版ドライラン: 手の前後上下左右→EEの正しい軸に写像(オフセット適用後シミュレーションで
  ±5cm一致)、到達不能で保持、リリース保持0.0°。
- 実ロボット: ユーザー操作で追従確認。手首符号・グリッパ方式は実機フィードバックで修正。
- 敵対的レビュー2回(velocity版・IK版)で計21件の指摘 → 全て修正または文書化。
  キネマティクスはURDF比3.9µm精度で独立検証済み。

## 6. 測定・運用の落とし穴

- **サーボバスの物理層**: アームを手で扱う作業(較正・姿勢測定)中にケーブルが緩み、
  「ID消失」→「パケット破損」→「全モーター無応答」まで実際に進行した。測定スクリプトは
  例外の**全種**(ConnectionError/SerialException/RuntimeError)で再接続リトライする。
- テレオペ実行中のシリアルポート排他は絶対(joystick編§8)— ユーザーが並行して
  teleopを起動していないか `fuser /dev/ttyACM0` で確認してから測定する。
- トルクONのままだとアームは手で動かせない(測定が全変位0.0°になる)。トルク解除は
  脱力落下に注意(カウントダウン+支え指示)。
